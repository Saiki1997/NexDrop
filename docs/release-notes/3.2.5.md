# NEXDROP 3.2.5

Fixes from the x.com/RoshyTV runs of 6–8 November.

## X videos that always failed with 503
- **A video X won't serve now downloads from another copy.** The same eight long videos failed with *503 Service Unavailable* on every run and every retry for three days. X has no working full-size MP4 for some long videos. NexDrop now checks each video's best MP4 first. If X refuses it, NexDrop tries the next MP4, then the HLS stream that the X app plays.
- Videos whose best MP4 works are queued exactly as before, so files you already have are still skipped.

## One bad file no longer pauses the whole site
- **Only different files count towards pausing a site.** Those eight videos were asked for again by the retry pass, failed again, and paused twimg.com. Every other queued X file then failed at once as *Site Paused*: 850 in one run. A file that already failed with a server error in this run no longer counts again.
- **Short pauses are waited out.** A file that reaches a site paused for 90 seconds or less waits and then downloads, instead of failing.

## Log
- *Scrape Failed: x.com/search… (403 Search results blocked by twitter)* no longer shows as a failed link on profile runs. X blocks search when you're not signed in, and the profile's media and posts were already read.
