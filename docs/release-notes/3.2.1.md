# NEXDROP 3.2.1

Fixes from a 3.2.0 run of a large SimpCity thread (5,574 saved, 3,011 failed).

## Pixeldrain
- **No more "maximum number of open download connections".** 186 files failed with this. Pixeldrain counts every connection against a small limit for free accounts, and 3.2.0 split large Pixeldrain files into 4 parts. Pixeldrain files now download in one stream. A file that still gets this answer waits 15 s and asks again (up to 5 minutes). That wait doesn't use up its attempts, and it's listed as *Rate limited* instead of *Sign-in needed*.
- Files Pixeldrain locks for "hotlinking" (its captcha) still fail with that reason. They download with a paid account's API key, or in a browser.

## Large files in parts
- **A part that fails no longer throws away the download.** When one part of a split file was refused (Pixeldrain 403, Bunkr 429/503), the whole `.part` file was deleted, even with hundreds of MB saved. The file now continues as one stream from the end of part 1. Switching to one stream doesn't use up an attempt either.
- **Servers set to one connection are not split.** With **Connections per server = 1**, Bunkr's CDN was still asked for 4 parts at once and answered *Server answered 429/503 to an extra connection*.

## Steady speed
- **Reconnects wait a little longer each time:** 1 s, 2 s, 4 s… up to 30 s. A Bunkr server that kept dropping the connection was asked again every second, 9 times in 2 minutes.
- Reconnects show in the log as information (*Download reconnecting*), not as *Download failed* errors.

## FlareSolverr
- **Only real bot checks go to FlareSolverr.** e-hentai's image servers (`*.hath.network`) answer original-size images that need an account with a plain web page. NexDrop sent each of them to FlareSolverr, which came back empty 24 times in one run. Pages with a DDoS-Guard or Cloudflare check are still cleared as before.
